# Textverarbeitung, Umleitungen & Pipes

F: Wie suchst du in der Datei log.txt nach allen Zeilen, die "ERROR" enthalten?
L: grep ERROR log.txt
L: grep "ERROR" log.txt
L: grep 'ERROR' log.txt
E: grep -i ignoriert Groß-/Kleinschreibung, -v kehrt die Suche um, -r sucht rekursiv.

F: Was macht das Zeichen ">" in "ls > liste.txt"?
A: Hängt die Ausgabe an liste.txt an
B: Schreibt die Ausgabe in liste.txt und überschreibt den alten Inhalt
C: Liest liste.txt als Eingabe
D: Vergleicht ls mit liste.txt
L: B
E: ">" überschreibt, ">>" hängt an.

F: Wie hängst du die Ausgabe von "date" an die Datei protokoll.txt an, ohne sie zu überschreiben?
L: date >> protokoll.txt
E: Doppelte spitze Klammer = anhängen.

F: Was macht die Pipe "|"?
A: Sie leitet die Ausgabe eines Befehls als Eingabe an den nächsten weiter
B: Sie führt zwei Befehle gleichzeitig unabhängig aus
C: Sie speichert die Ausgabe in einer Datei
D: Sie trennt Kommentare vom Befehl
L: A
E: Beispiel: ls | wc -l zählt die Einträge im Verzeichnis.

F: Wie zählst du die Zeilen der Datei namen.txt?
L: wc -l namen.txt
L: wc -l < namen.txt
L: cat namen.txt | wc -l
E: wc zählt Zeilen (-l), Wörter (-w) und Zeichen (-c).

F: Warum steht vor "uniq" fast immer "sort"?
A: uniq funktioniert nur mit Zahlen
B: uniq entfernt nur direkt aufeinanderfolgende doppelte Zeilen
C: sort ist für uniq Pflicht, sonst gibt es einen Fehler
D: Das ist nur eine Stilfrage
L: B
E: Erst sortieren, damit Duplikate nebeneinander stehen: sort datei | uniq (oder sort -u datei).

F: Wohin leitet "2>" um?
A: Die Standardausgabe
B: Die Standardeingabe
C: Die Fehlerausgabe (stderr)
D: In die zweite Datei
L: C
E: Kanal 0 = stdin, 1 = stdout, 2 = stderr. "2>/dev/null" verwirft Fehlermeldungen.

F: Mit welchem Befehl schneidest du die erste Spalte aus einer durch Doppelpunkte getrennten Datei wie /etc/passwd aus?
L: cut -d: -f1 /etc/passwd
L: cut -d ':' -f1 /etc/passwd
L: cut -d: -f 1 /etc/passwd
L: cut -f1 -d: /etc/passwd
E: -d legt das Trennzeichen fest, -f die Feldnummer.

F: Welcher Befehl gibt eine Ausgabe gleichzeitig auf dem Bildschirm aus UND schreibt sie in eine Datei?
A: tee
B: cat
C: echo
D: split
L: A
E: Beispiel: ls | tee liste.txt

F: Wie gibst du den Text "Hallo Welt" auf dem Bildschirm aus?
L: echo Hallo Welt
L: echo "Hallo Welt"
L: echo 'Hallo Welt'
E: echo schreibt seine Argumente auf die Standardausgabe.

F: Wie findest du mit einem regulären Ausdruck alle Zeilen, die ERROR oder CRITICAL enthalten?
L: grep -E "ERROR|CRITICAL" portal.log
L: grep -E 'ERROR|CRITICAL' portal.log
L: grep -E "CRITICAL|ERROR" portal.log
L: grep -E 'CRITICAL|ERROR' portal.log
L: egrep "ERROR|CRITICAL" portal.log
E: -E aktiviert erweiterte reguläre Ausdrücke, | bedeutet "oder".

F: Welcher reguläre Ausdruck passt auf "WK-" gefolgt von genau sechs Ziffern?
A: WK-*
B: WK-[0-9]{6}
C: WK-??????
D: WK-[6]
L: B
E: Mit grep -oE 'WK-[0-9]{6}' werden nur die Treffer ausgegeben. * und ? sind hier Shell-Wildcards, keine Regex.

F: Was ist der Unterschied zwischen Shell-Wildcards und regulären Ausdrücken?
A: Kein Unterschied
B: Wildcards wählen Dateinamen aus (die Shell löst sie auf), reguläre Ausdrücke beschreiben Textmuster in Inhalten (z. B. für grep)
C: Reguläre Ausdrücke funktionieren nur in Python
D: Wildcards gibt es nur unter Windows
L: B

F: Was passiert bei "sort namen.txt > namen.txt"?
A: Die Datei wird korrekt sortiert
B: Die Datei ist danach leer, weil die Umleitung sie leert, bevor sort sie liest
C: sort meldet einen Fehler und nichts passiert
D: Die Datei wird doppelt so lang
L: B
E: Lösung: sort -o namen.txt namen.txt oder in eine neue Datei schreiben und danach umbenennen.

F: Wo landen bei "befehl 2>&1 > datei.txt" die Fehlermeldungen?
A: In datei.txt
B: Auf dem Bildschirm
C: In /dev/null
D: Nirgends
L: B
E: Umleitungen werden von links nach rechts ausgewertet. 2>&1 kopiert stderr auf das damalige stdout (Bildschirm). Richtig für beides in die Datei: befehl > datei.txt 2>&1.

F: Welchen Dateideskriptor hat stderr?
L: 2

F: Wie leitest du nur die Fehlermeldungen von ls in die Datei fehler.txt um?
L: ls 2> fehler.txt
L: ls 2>fehler.txt

F: Wie zeigst du die letzten 5 Zeilen an, die ERROR enthalten?
L: grep ERROR portal.log | tail -n 5
L: grep ERROR portal.log | tail -5
L: grep "ERROR" portal.log | tail -n 5
L: grep 'ERROR' portal.log | tail -n 5
L: grep "ERROR" portal.log | tail -5

F: Wie legst du einen Alias ll für "ls -lah" an (für die aktuelle Sitzung)?
L: alias ll='ls -lah'
L: alias ll="ls -lah"
E: Dauerhaft wird er, wenn du die Zeile in ~/.bashrc einträgst. Die Definition zeigt alias ll oder type ll.

F: Warum ist less für große Logdateien besser geeignet als cat?
A: less verändert die Datei nicht
B: less zeigt seitenweise an, erlaubt Vor- und Zurückblättern und Suchen, ohne alles auf einmal auszugeben
C: cat kann keine Logdateien lesen
D: less komprimiert die Datei
L: B
